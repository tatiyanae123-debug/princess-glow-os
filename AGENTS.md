# Glow OS Agent Rules

Before changing any UI, read:
- `docs/GLOW_LIQUID_CRYSTAL_CONSTITUTION.md`
- `docs/glow-os-3-design-rulebook.md`

The Liquid-Crystal Constitution is the current visual authority. Where the older White Editorial rulebook conflicts with it, the Constitution wins. The approved reference is the dark luminous Liquid-Crystal Glow OS system, not the former white editorial shell.

These rules are mandatory:

1. Preserve Next.js App Router, TypeScript, Tailwind, Neon PostgreSQL, Drizzle ORM, Auth.js, Server Actions and Zod. Do not add a second auth, database, ORM or styling framework.
2. Global visual foundation is deep midnight/navy atmosphere with translucent climate-colored Glow Matter, luminous white typography and restrained internal refraction.
3. Permanent primary navigation is Today / Plan / Life / Brain / Create. Secondary rooms live within those worlds or are reached through Search / Ask Glow.
4. Ask Glow is one universal action layer. Do not duplicate global assistant launchers.
5. Every room must answer quickly: Where am I? What matters now? What should I do next?
6. First viewport should usually contain 3–5 meaningful elements. Use progressive disclosure.
7. Every visible control must have a real destination, form, action or safe preserved fallback. No fake buttons.
8. Visual styling must never change pointer behavior, handlers, routes, focus order, or working data flows.
9. Decorative layers must use pointer-events:none and must never cover controls with interaction-blocking z-index values.
10. Use an 8px spacing grid and stable touch targets.
11. Every major room supports Focus Mode where relevant.
12. Prefer Now / Next / Later as the shared temporal hierarchy.
13. Page climate changes color and atmosphere, not navigation structure.
14. Today uses pearlescent dawn; Plan temporal lilac-blue; Body mineral aqua/green; Beauty rose opal; Money emerald; Brain violet-blue; Create shifting opal; Home botanical mineral; Work slate crystal.
15. New UI inherits Glow Matter and shared Glow physics. Do not introduce unrelated visual systems.
16. Meaningful intelligence may dispatch `glow:intelligence`, `glow:command-complete`, or `glow:action-complete` for the universal aurora response.
17. Motion respects `prefers-reduced-motion` and never blocks task completion.
18. Never delete routes, database workflows, integrations or user data to achieve a redesign.
19. Preserve room context such as selected objects, active steps and current views where appropriate.
20. Verify iPhone, iPad and desktop behavior, keyboard/focus accessibility, and all visible actions before shipping.

Acceptance standard: a screen is not finished until it both works and unmistakably resembles the approved dark Liquid-Crystal Glow reference.
