# Glow OS — Batches I–K, Steps 65–76

## Batch I — Real Runtime Conversion, Steps 65–68
The Batch H migration manifest now has a runtime-conversion planning layer. Eligible surfaces resolve to the Global Shell, registered shared engines and canonical object dependencies while retaining legacy entry compatibility. Ambiguous or blocked surfaces remain review items. This contract does not delete existing routes.

## Batch J — Automatic Visual System, Steps 69–72
Visual inheritance is formalized as Global visual laws → World → Room → Template → State, with energy-mode projection layered on top. The QA matrix covers iPhone, iPad and desktop plus empty, populated, loading and error states and Low/Normal/High/Recovery energy modes. Repeated visual drift must be repaired at the shared token/template ancestor rather than patched page by page.

## Batch K — QA Factory, Steps 73–76
The required QA pipeline is Build → Route → Data → Actions → State → History → Responsive → Accessibility → Visual → Runtime → Regression. Failures are deduplicated into shared root causes by owner/gate/message so one ancestor fix can clear many affected surfaces. Release remains gated by required QA and Golden exceptions.

## Boundary
These batches add runtime-conversion, visual-inheritance and QA-factory machinery. They do not claim every live route has already been converted or visually approved. They do not merge main, ship production or authorize legacy deletion without parity evidence.
