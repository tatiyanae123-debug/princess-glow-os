# Glow OS — Batch B

Batch B continues the real Skincare pilot without deleting the current route or its data.

## Global Shell ownership
Persistent Glow identity, world/room/experience context, World Fold, spatial back, Search, Ask Glow, Shakti, Attention Center, Quick Capture, mode, sync and overlay architecture are declared Global Shell responsibilities. The legacy Skincare `ReferenceRail` and any local persistent shell/navigation become retirement candidates only after parity.

## T02 Atelier exception
Skincare Home remains a registered T02 composition exception because its Atelier arrival/environment is reference-critical. The exception is deliberately narrow: it can own the Atelier composition and environment, but cannot override Global Shell, canonical identities, global overlays, responsive rules or accessibility contracts. Golden visual approval remains required.

## Thin-route transition
The five Batch A pilot identities now have explicit thin-route bindings: Home, Product Library, Product Detail, Guided Routine and Progress. Legacy query-param entry points can resolve to registered experience identities during migration. The existing `/beauty/skincare` route remains intact until parity and QA pass.

## Preservation + QA gate
No route retirement is authorized until canonical data/history are preserved, the build is READY, runtime errors are clear, responsive/accessibility QA passes and the T02 Golden exception is approved.
