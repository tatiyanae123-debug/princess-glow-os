# Glow OS — Steps 14–17

## Step 14 — Close the Face Skincare family lock
Face Skincare remains BUILDING until every existing lock gate passes: architecture, functional behavior, canonical data, intelligence, responsive behavior, accessibility, golden visual comparison, and regression. Do not mark it LOCKED merely because the registry exists. The lock freezes inheritance assignments, object identity rules, room tokens, session state-machine behavior, overlays, and responsive laws after validation.

## Step 15 — Beauty Routine Engine
Create one shared Beauty routine engine rather than separate routine logic inside Skincare, Hair, Makeup, Body, Nails, Brows/Lashes, Oral Beauty, Gua Sha, and Maintenance.

Required behavior:
- Distinct canonical Routine and Routine Session objects.
- Full, Normal, Quick, Bare Minimum, and Recovery modes.
- Conditional steps based on state/context.
- Active products/tools reference canonical Beauty objects.
- Physical storage/location can be attached to steps.
- Clinician/manufacturer guidance outranks Glow optimization.
- Completion/history belongs to the session/object, not the page.

Executable contract: `src/lib/glow/beauty-routine-engine.ts`.

## Step 16 — Beauty Maintenance + Grooming Calendar
Create one cadence engine used by all Beauty maintenance experiences.

It supports daily, every-few-days, weekly, biweekly, monthly, seasonal, appointment, event, and condition-triggered maintenance. A maintenance object may carry preparation routines, recovery routines, required products/tools, appointment type, source/provenance, and preserved source conflicts.

This is a projection into the canonical Glow calendar. It must not create a second Beauty-only calendar database.

Executable contract: `src/lib/glow/beauty-maintenance-engine.ts`.

## Step 17 — Nails + Brows + Lashes + Oral Beauty
Register these as Beauty rooms inheriting the Global Glow Constitution, Beauty constitution, shared master templates, Routine Engine, Maintenance Engine, canonical Beauty inventory, and canonical Calendar.

Do not design them as four unrelated mini-apps. Each room may specialize atmosphere and domain data while inheriting Home, Library, Detail, Guided, Today/Intelligence, Calendar, Progress, Completion, Ask Glow, history, state and overlay behavior.

Executable registry: `src/lib/glow/beauty-grooming-registry.ts`.

## Speed law after Step 17
Future Beauty families should be implemented by configuration + canonical objects + shared engines first. A new page implementation is allowed only when an existing template cannot express the experience and the exception is registered explicitly.
