# Glow OS — Steps 40–46

Step 40 remains the canonical object adapter layer. Steps 41–46 move Glow from architecture expansion into migration-factory mode.

## 41 Migration command
Classifies an existing surface, creates a preservation-first migration plan, binds the target experience/template/environment and separates ready work from review-required work. It never auto-deletes a live route.

## 42 Beauty factory proof
Defines the full Beauty migration plan across Skincare, Hair, Makeup, Body, Nails, Brows, Lashes, Oral, Fragrance, Tools/Devices, Gua Sha and Maintenance. Skincare and Gua Sha remain explicit exception-sensitive rooms.

## 43 Automatic visual + functional QA
Defines mandatory registry, typecheck, build, route-load, runtime, state, action, context, responsive, accessibility, canonical-data, history and provenance gates. Vercel READY satisfies only the deployment/build portion. Golden visual approval remains separate.

## 44 Bulk migration waves
A Today/Planning/Routines; B Closet/Fitness-Wellness; C Money/Home/Food/Travel/Career-Life; D Brain/Create. A failed family improves the shared factory rather than receiving page-by-page patches.

## 45 Inheritance audit
Detects duplicate navigation/object identity, page-owned architecture, rogue CSS, duplicate overlays/state machines, disconnected history, token/context bypasses and dead UI.

## 46 Factory lock
Global Shell, templates, canonical objects, state machines, overlays, navigation and responsive rules can lock only when the latest build is READY, automatic QA passes, blockers are zero and Golden approval is present where required.
