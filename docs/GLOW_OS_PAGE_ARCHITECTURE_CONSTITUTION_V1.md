# Glow OS Page Architecture Constitution v1

Status: **ADOPTED · CONFORMANCE IN PROGRESS**

This document is a permanent system-wide law for current and future Glow OS pages, rooms, studios, specialists, redesigns, migrations, code review and QA. It governs existing World waves instead of creating a new software wave. It may change only through an explicit architecture amendment.

The governing formula is:

**One Global Glow Shell + one World Environment + one approved page architecture + one projection of shared Glow Objects.**

The constitutional top-level Worlds remain **Today, Plan, Life, Brain and Create**. Beauty may remain a runtime compatibility environment during migration, but it does not amend the permanent World model by itself. Work remains a Life domain.

## Four layers

1. **Global Glow Shell.** Permanent identity, current World/location, navigation, back/close, Ask Glow, user identity, energy/mode, search, Attention Center, privacy, save/sync, undo/redo, global capture, responsive behavior, accessibility and transitions. Pages may not recreate it.
2. **World Environment.** World-specific atmosphere, depth, motion and tools without separate shell physics.
3. **Approved Page Architecture.** Internal structure selected by the page's job, organizing dimension and user state.
4. **Canonical Glow Object Projection.** Every screen reads and writes the same object identity, state, history, provenance, permissions and relationships rather than page-private copies.

Batch numbers, migration rounds and internal architecture labels are not user-facing navigation.

## Approved architecture library

The base library is Contextual Brief, Transitional Brief, Operational Calendar, Scenario Studio, Object Workspace, Guided Experience, Adaptive Program Workspace, Spatial Operations Map, Relationship Care System, Knowledge Graph, System Constellation, Living System Map, Cultivation Dashboard, Embodied State Monitor, Personal Domain Studio and Resource Command Center.

The Life, Capture and Care amendment adds Integrated Domain Hub, Ambient Capture Field, Progression Command Center, Shopping Operations Workspace and Cross-Domain Protocol Orchestrator. Precision Guided Studio specializes Guided Experience and Personal Domain Studio. Restorative Care Workspace specializes Embodied State Monitor.

The Today Execution amendment adds Living Day Orchestrator, Adaptive Replanning Studio, Day-Phase Workspace, Immediate Horizon, Event Workspace, Protected Execution Environment and Contextual Decision Resolver. Adaptive Replanning Studio specializes Scenario Studio. Event Workspace specializes Object Workspace. Morning Brief remains Contextual Brief. Tomorrow Preview remains Transitional Brief.

The executable registry in `src/lib/glow/architecture-constitution.ts` defines purpose, permitted Worlds, organizing dimension, required and optional regions, center-stage behavior, inspector behavior, supported modes and objects, phone transformation, accessibility contract, empty/loading/error/offline behavior, prohibited uses, specialization parents and trust rules.

## Architecture selection law

Select architecture by asking: what is the user trying to do; what kind of information is being handled; what deserves the center; what is the primary organizing dimension; is the user observing, exploring, deciding, planning or performing; is the state hypothetical or committed; and does the job require precision, immersion or both.

Functional differences must survive visual convergence. Calendar keeps a precise time grid. Scenario Studio keeps draft possibility separate from committed reality. Home keeps spatial operations. Guided Experiences keep active-step controls. Object Workspaces keep dense object context. Relationships remain person-centered. Knowledge Graph remains connection-based. Body remains signal-centered. Money remains numerically exact. Studios retain domain tools. Briefs remain reduced and contextual.

## Merge and no-duplication laws

- Gua Sha variations use one Guided Experience family.
- Home designs become views of one spatial Home system.
- Relationships use Connection and People views over the same Person Objects.
- Dark/light Notes Web become modes of one Knowledge Graph.
- Habit ecosystem and garden share canonical Habit Objects.
- Movement Studio is one Adaptive Program Workspace and launches a separate Guided Workout Experience.
- Body, Fitness, Wellness, Today and routines read one shared body/energy state.
- Studios use canonical Product Objects from inventory.
- Events in Calendar, Today, Next Up, Event Workspace and Life are one Event Object.
- Repeated Money, Fitness and Body reference designs do not create new pages or data stores.

## Life, Capture and Care family

### Food · Integrated Domain Hub

Food coordinates nutrition, meals, recipes, groceries, pantry, supplements, hydration, tracking, goals and insights. Its flow is **understand nourishment → choose/plan meals → confirm ingredients → shop if needed → prepare → eat → log → learn**. A recipe added to a meal plan generates ingredient requirements against the same Pantry and Grocery objects. Food may not create duplicate grocery items, pantry items, recipes, meal plans, nutrition records or supplements. The editorial kitchen lives inside the Global Glow Shell, never beside a second desktop/sidebar navigation system.

Required views: Overview, Nutrition, Meals, Recipes, Groceries, Pantry/Food Inventory, Supplements, Food Journal and Insights.

### Thoughts · Ambient Capture Field

Thoughts is a persistent low-pressure incubation environment, distinct from a one-time Brain Dump and distinct from the established-knowledge Notes Web. It accepts text, voice, image, document, link, handwriting, emotional signals, sensory notes, questions and unfinished ideas. Flow: **capture → preserve original form → incubate → identify similarity → suggest structure → approve conversion → connect**. Suggested grouping remains explainable and reversible. Private mode governs storage, AI processing, connection suggestions and visibility.

Lifecycle: Captured → Incubating → Grouped → Note/Task/Project/Reference, with Incubating → Archived available.

### Money · Resource Command Center

Maintain one Money system over canonical accounts, balances, transactions, bills, subscriptions, budgets, goals, commitments, available funds and attention items. No decorative totals. Account totals reconcile to included records. Available funds use a visible rule. Investments are not silently mixed with spendable cash. Sync timestamps and provenance are visible. Pending and posted transactions remain distinct.

### Work · Progression Command Center

Work coordinates current role, applications, opportunities, contacts, availability, compensation, skills, portfolio, schedule, career direction, decisions and history over time. Individual applications open as canonical Object Workspaces. Work is a Life domain, not a new top-level World.

### Grocery · Shopping Operations Workspace

Grocery coordinates list building, household inventory, recipe needs, reorders, stores, prices, budget context, aisles, shared shopping and purchase completion. Item states are suggested, needed, urgent, added, assigned, in cart, purchased, unavailable, substituted, removed and restocked at home. Grocery shares objects with Food, Recipes, Meal Planning, Pantry, Home Inventory, Money, Calendar and People/Shared Lists. It consumes budget information but does not own the financial source of truth.

Flow: **detect need → confirm inventory → add → choose store → optimize price/route → shop → check off → update inventory and spending**.

### Makeup Studio · Precision Guided Studio

Makeup combines a face map or live mirror, application stages, canonical owned Beauty Inventory products, desired finish/coverage, occasion/time and lighting/camera context. It respects sensitivities, allergies, expiration, compatibility, eye/lip safety, skin condition, exact shade identity and camera permission. It may not maintain a private product list.

### Beauty Command Center · Cross-Domain Protocol Orchestrator

This system coordinates one real preparation deadline across skincare, hair, makeup, body care, fragrance, closet/dressing, gathering items and travel buffer. It reads the event and leave-ready time, then sequences existing Studio and Routine Objects with absorption, drying/setting, dependency and conflict timing. Flow: **read event → calculate leave-ready deadline → choose effort/result → generate sequence → resolve conflicts → execute modules → final check → leave**.

### Wellness Restoration · Restorative Care Workspace

Restoration reads the same Body state used by Today, What Now, Fitness, routines, Morning Brief and Tonight. It converts signals into a reduced-demand recovery plan and must distinguish ordinary tiredness, user-reported symptoms, measured data, inferred state, medication effects and potentially urgent symptoms. Concerning symptoms trigger escalation behavior rather than being treated as ordinary self-care.

### Movement Studio and Body Awareness

Movement Studio remains one Adaptive Program Workspace and launches Guided Workout Experience for live execution. Body Awareness remains one Embodied State Monitor. These repeated references must not create separate systems or competing energy calculations.

## Required cross-system flows

- Food/Grocery: Meal Plan → Recipe → Ingredient Need → Pantry Check → Grocery List → Purchase → Home Inventory → Meal Plan.
- Body/Wellness/Fitness: Body State → What Now/Fitness Adaptation/Restoration Plan → Workout or Care Result → Body State.
- Event/Beauty: Event → Leave-Ready Time → Beauty Protocol → Skin/Hair/Makeup → Final Look.
- Thoughts/Brain: Capture → Thought Incubation → Grouping → Note/Task/Project → Knowledge Graph.

## Today Execution family

Today is not one long dashboard. It is a changing set of projections into one canonical active day.

The execution loop is **Morning Brief → Today Day View → What Now? → Next Up → Event or Focus Session → Later → Tonight → Tomorrow Preview**, with Replan My Day repairing the active day and returning to Day View.

### Today Day View · Living Day Orchestrator

Today organizes lived relevance rather than duplicating Calendar. It combines time, energy, mode, events, tasks, routines, habits, preparation, travel, buffers, progress, unfinished work and tomorrow's first commitments. Calendar remains the authoritative committed time record.

### Replan My Day · Adaptive Replanning Studio

Replan begins from committed reality and produces a temporary proposal. Change states include unchanged, moved, shortened, extended, protected, delegated, deferred, cancelled, replaced, awaiting approval and applied. Glow may propose but may never silently move committed events. Suggestions must explain what changes, why, conflicts resolved, possible disruption, affected people and approval requirements.

### Tomorrow Preview · Transitional Brief

One canonical Tomorrow Preview transforms next-day Calendar, Planning, Projects, routines, people, weather, places, files and preparation requirements into a small readiness experience.

### Tonight and Later · Day-Phase Workspace

Morning, Between/Midday, Later/Afternoon, Evening and Night use one phase frame with different emphasis, density, pace, imagery, energy expectations and actions. Later protects realistic afternoon capacity and transition to evening. Tonight shifts emphasis toward nourishment, completion, restoration, preparation, reduced stimulation and sleep. Recovery/Cancel Everything mode makes the phase shorter and gentler.

### Next Up · Immediate Horizon

Next Up prepares one near-term block, including hidden changing/gathering/travel/shower/setup transitions and required items. It prepares the block; Guided Experience runs the procedure inside the block.

### Event Workspace

One canonical Event Object moves through Before, Starting Soon, In Progress, Ended, Follow-up Required and Complete. Before emphasizes preparation. During emphasizes agenda/notes. After emphasizes decisions/follow-ups. Calendar, Today, Next Up and Event Workspace are projections of that same object.

### Focus Session · Protected Execution Environment

Focus supports one objective, timer, pause/resume, extension, early completion, subtasks, required files, ambient audio, parked thoughts, blockers, interruption recovery, result and actual versus planned duration. It is distinct from Guided Experience because the user determines the work content rather than following a procedural recipe.

### What Now? · Contextual Decision Resolver

What Now? considers time available, shared energy/physical state, mental load, focus requirement, urgency, importance, deadlines, location, resources, preparation, dependencies, operating mode, priorities, capacity, recent progress, preferences, resistance and recovery needs. Every recommendation exposes what to do, why, duration, expected energy demand, urgency, related goal/commitment, resources, possible downside, alternatives, confidence and source information.

**Glow recommends. The user decides.** Recommendation language must not pressure the user or disguise a suggestion as an obligation.

### Morning Brief · Contextual Brief

Morning Brief remains one configuration combining wake state, weather, shared energy, care/medication context, food, clothing, first appointment and initial priorities. It must not create a separate dashboard shell.

## One active-day object model

Today surfaces share active day, events, tasks, routines, priorities, state, energy, capacity, decisions and progress. They never maintain separate versions.

Object lifecycle: Planned → Upcoming → Preparing → Active ↔ Paused → Completed → Reflected. Planned may become Replanned then Upcoming. Active may become Deferred then Planned.

## Ask Glow naming

The global entry point is **Ask Glow**. If Shakti remains a named intelligence presence, Shakti lives inside the Ask Glow system and may not replace the global entry point inconsistently.

## Architecture manifests and enforcement

`src/lib/glow/architecture-constitution.ts` is the executable Architecture Registry and declares manifests for the Life/Capture/Care and Today families. `ArchitectureContextBridge` projects the active architecture into the Global Glow Shell. New pages should fail architecture QA when undeclared or when their World, data-source, permission or action contracts are missing.

Architecture manifests declare World, room/studio, architecture, primary object, intent, center focus, supporting regions, inspector, data sources, permissions, actions, canonical system and migration/conformance state.

## Reusable architecture frames

`src/components/glow/architecture-frames.tsx` provides the base and amendment frames. Frames define structural behavior, not page-specific visual content. `src/app/architecture-frames.css` provides desktop/tablet/phone transformation. Inspectors collapse into an end-of-flow sheet-like region on phones rather than shrinking a desktop canvas. The Global Glow Shell remains available without duplication.

## Architecture Convergence governance

This work does not restart the project and does not create Wave 11. It governs the existing completion waves through six internal architecture-convergence stages:

A. Constitution. Lock the four-layer law, library, selection rules and merge/preserve rules.
B. Census. Audit route architecture, duplicate objects, shell violations, state duplication and migration blockers.
C. Shell + Registry. Architecture Registry, manifests, Global Shell projection and enforcement.
D. Reusable Frames. Structural frames, responsive transformations, states, inspectors and transitions.
E. Page Migration. Repair conformance inside the existing Today/Plan, Beauty, Fitness/Wellness, Life and Brain/Create waves.
F. Architecture QA + Lock. Verify structure, canonical data, responsive behavior, accessibility, transitions, provenance, permissions and duplicate removal.

Already-locked or completed work receives an architecture-conformance pass only. Unrelated design decisions do not reopen.

## Lock criteria

The Constitution itself is adopted as governing law, but family labels remain **CONFORMANCE REQUIRED** until runtime migration and evidence satisfy all criteria.

### Life Domains, Capture and Care Family

May become `LOCKED` only when every target route has one primary architecture; Money/Fitness/Body are not duplicated; Food/Grocery share canonical items/inventory; Beauty Command Center uses existing Studio/Routine Objects; Makeup uses canonical owned products; Thoughts feeds the same Brain Graph as Notes; Work uses canonical people/events/applications/projects; Restoration reads shared health/energy state; numerical data exposes provenance; AI organization is explainable/reversible; desktop/iPad/iPhone pass; and sensitive health/money/thought permissions pass.

### Today Execution Family

May become `LOCKED` only when all ten manifests exist; local duplicate shells are removed; all surfaces inherit the Global Glow Shell; active day has one canonical source; transitions work; What Now is evidence-backed; Replan requires approval; Focus records results; Event Workspace follows lifecycle; phase pages adapt to mode/energy; desktop/iPad/iPhone pass; accessibility/reduced motion pass; loading/empty/offline/error states exist; and visual + functional QA passes.

Target labels after evidence:

- **Glow OS Architecture Constitution v1 · Life Domains, Capture and Care Family: LOCKED**
- **Glow OS Architecture Constitution v1 · Today Execution Family: LOCKED**

Until those gates are evidenced, code must report conformance work honestly rather than declaring a lock.
