# Glow OS — Universal Shell Harmonization Lock

**Status:** AUTHORITATIVE / PERMANENT  
**Date:** 2026-09-06  
**Scope:** Every existing and future Glow OS route, room, world, subpage, object view, responsive composition, prototype and implementation.

This lock extends `GLOW_CURRENT_GLOBAL_NAVIGATION_LOCK_2026-09-05.md` and supersedes any older page-local shell, permanent-sidebar, global-header, fixed bottom-bar, breadcrumb, or Today-only navigation authority.

## Core invariant

Glow OS has one permanent invisible navigation skeleton. It is mounted once at the application root and follows the user everywhere.

Rooms may change architecture, atmosphere, dominant object, material, scale and signature interaction. Rooms may **not** redesign the operating system around themselves.

The user should experience one house with many rooms, not many websites sharing a visual palette.

## One stable outer frame

The Glow OS world boundary is app-level infrastructure. It does not randomly disappear, become thicker, shrink inward, change corner radius, or create a second enclosing rectangle because a room changed.

## Three intentional enclosure states

**Open World** is used for atmosphere, transition and temporal/relational horizon experiences. The room may breathe nearly to the outer Glow OS boundary. Do not add a generic giant inner card.

**Structured Room** is used when several related things need architectural organization. Structure comes from the room and its objects, not a generic rectangle around the page.

**Protected Chamber** is used for intentionally narrowed attention such as Focus Session, Replan My Day, immersive routine steps or editing modes. The surrounding world may recede, but the permanent shell remains available and understandable.

## Permanent top geometry

Every room inherits the same top baseline:

- upper left: Glow OS identity plus the stable Return Anchor zone
- top center: current major world identity plus the subtle depth signal
- upper right: Shakti, with **Ask Glow** as the action that unfolds the one persistent intelligence

The page title belongs to the room architecture. It may not rebuild the global top band.

## Shakti and Ask Glow naming law

**Shakti = the intelligent presence.**  
**Ask Glow = the action/conversation state.**

There is one Shakti placement in the permanent shell. Activating it opens the existing centralized Ask Glow conversation. Page-local Ask Glow controls may remain only as contextual aliases to that same intelligence.

## One Glow Current Rail

The left-edge movement system is one app-level Glow Current Rail, not a permanent conventional sidebar.

- the current room is the clearest local signal
- nearby destinations appear as subtle nodes
- labels reveal on touch, hover, keyboard focus or explicit expansion
- the rail remains in the same conceptual position and keeps the same movement meaning across rooms
- each world may provide different nearby destinations, but it may not create a new rail runtime

Desktop may use a vertical edge field. iPad may use a thinner touch-expanding edge current. iPhone may use a compact edge-held current. Meaning remains identical.

## One contextual Return Anchor

The Return Anchor is one physical object with one location, material behavior and motion language. Its destination is contextual so depth is understandable:

- deep object/subpage → parent room
- room → current major world
- major world root → Today
- Today root state → no unnecessary return action while shell geometry remains stable

This contextual parent behavior replaces inconsistent Back to Today / Today / Back objects without creating conventional breadcrumbs.

## Universal depth signal

The top-center orientation layer includes a subtle connected depth signal. It is not a website breadcrumb trail. Previous levels remain softer, while the active depth is fully legible. Accessibility modes may expose the complete text hierarchy.

## One bottom action host

Glow OS has one universal three-zone bottom action layer:

- left: verified local room/view action or Reverse the Current
- center: verified primary action for the current mode; when none is registered, World Fold remains the stable system action
- right: verified system state, save/undo/completion state, or another real contextual action

Rooms may register real actions into this host. They may not create a competing fixed global bottom navigation bar. No fake action may be inserted merely to fill a slot.

## No navigation inside page templates

A room may have local transforms, objects and depth, but it should not reproduce ordinary pill tabs such as `Overview / Products / Progress / History / Settings` as its primary movement system. Those concepts should become room-specific transformations where practical: drawers, mirrors, timelines, material layers, stages, archives, object depth or other meaningful information surfaces.

## One dominant orientation contract

At any moment the user should understand:

1. Where am I?
2. How do I go deeper?
3. How do I return?
4. How do I ask Shakti / Ask Glow?

Secondary controls must not compete with those answers.

## Today synchronization

Today rooms inherit the same root shell.

- Morning Brief: Open World; no unnecessary Return Anchor
- What Now: Structured Room
- Focus Session: Protected Chamber; surrounding information recedes while Return Anchor and Shakti stay available but quiet
- Event Detail: Structured Room inside Today, not a separate calendar app shell
- Next Up: Open transition corridor
- Later: continuation farther along the same temporal current
- Tonight: same navigation geometry; only climate changes
- Tomorrow Preview: remains attached to Today
- Replan My Day: Protected/Edit Chamber
- Day View: neutral temporal overview; NOW, NEXT, LATER, TONIGHT and TOMORROW are regions of one timeline rather than five primary tabs

No Today-only navigation authority may replace the root Glow Current shell.

## All other worlds inherit the same shell

Plan, Life, Brain and Create use the same Glow OS identity, Return Anchor physics, depth language, Shakti placement, World Fold, Glow Thread, continuity and responsive meaning. Their local Navigation Identity changes. The operating-system shell does not.

## Responsive law

Navigation logic is universal. Geometry adapts.

Desktop can use cursor proximity, hover, trackpad and a vertical edge Current. iPad can use a thinner touch/hover Current and larger spatial previews. iPhone uses a compact edge-held Current suitable for one-handed reach. Do not introduce a five-icon bottom tab bar.

Across devices, Return Anchor, World Fold, depth, Reverse the Current and Shakti retain the same conceptual meaning.

## AppShell engineering law

`AppShell` is a room-content and atmosphere host only. It must not own a permanent Sidebar, GlobalHeader, TodayNavigationAuthority-like runtime, world tab row or duplicate Shakti trigger. The root `GlowCurrent` owns the universal shell.

## Legacy migration

Legacy page-local rails, old global headers, old fixed docks and conventional navigation may remain temporarily only when required to preserve a working local feature during migration. They are compatibility surfaces, not design authority. New work must not copy them.

Where the root shell provides the same global function, the duplicate legacy global control should be removed or suppressed without deleting the room's actual local functionality.

## Accessibility

Futurism may never make orientation inaccessible. Provide visible focus, keyboard access, reduced motion, sufficiently large targets, screen-reader labels, persistent names when requested, dyslexia-friendly text support and explicit text navigation fallback where needed.

## Completion test

A room is not complete unless:

- the stable outer Glow OS boundary is present
- the universal top geometry is inherited
- Shakti is in the canonical position and opens the same Ask Glow runtime
- Glow Current Rail remains available
- Return Anchor behavior is contextual and consistent
- the depth signal is truthful
- World Fold remains reachable
- Glow Thread/recent-path memory survives travel
- the bottom action host remains the universal fixed action layer
- page-local global navigation does not compete with the root shell
- enclosure is intentionally Open, Structured or Protected
- iPhone, iPad and desktop preserve the same navigation meaning
- reduced-motion and keyboard behavior remain usable

## Final invariant

**Every Glow OS page inherits the same invisible navigation skeleton. Rooms may change their architecture, materials, atmosphere, scale, dominant object and interaction. They may not redesign the operating system around themselves.**

**Glow OS is one continuous house with many rooms. Glow Current is the permanent movement system that follows the user through all of them.**
