# Glow OS — Universal Shell Harmonization Lock

**Status:** AUTHORITATIVE / PERMANENT  
**Date:** 2026-09-06  
**Scope:** Every existing and future Glow OS route, room, world, subpage, object view, responsive composition, prototype and implementation.

This lock extends `GLOW_CURRENT_GLOBAL_NAVIGATION_LOCK_2026-09-05.md` and supersedes any older page-local shell, permanent-sidebar, global-header, fixed bottom-bar, breadcrumb, or Today-only navigation authority.

## Core invariant

Glow OS has one permanent invisible navigation skeleton. It is mounted once at the application root and follows the user everywhere.

Rooms may change architecture, atmosphere, dominant object, material, scale and signature interaction. Rooms may **not** redesign the operating system around themselves.

The user should experience one house with many rooms, not many websites sharing a visual palette.

## 1. One stable outer frame

The Glow OS world boundary is app-level infrastructure.

It does not randomly disappear, become thicker, shrink inward, change corner radius, or create a second enclosing rectangle because a room changed.

A room may be visually open, structured, or protected, but the outer Glow OS boundary remains stable.

## 2. Three intentional enclosure states

Every room uses one of three states. Enclosure is meaningful, never accidental.

### Open World

For atmosphere, transition, relationships, travel, memory and temporal horizon experiences. The room may breathe nearly to the outer Glow OS boundary. Do not add a generic giant inner card.

Typical Today examples: Morning Brief, Next Up, Later, Tonight, Tomorrow Preview.

### Structured Room

For working with several related things. Structure comes from the room's architecture and objects, not from wrapping the entire page in a generic rectangle.

Typical examples: What Now, Event Detail, Closet, Home, Food, Calendar, Finance.

### Protected Chamber

For intentionally narrowed attention such as Focus Session, Replan My Day, immersive routine steps, or editing modes. The surrounding world may recede, but the permanent shell remains available and understandable.

## 3. Permanent top geometry

Every room inherits the same top baseline.

- **Upper left:** Glow OS identity plus the stable Return Anchor zone.
- **Top center:** current major world identity plus the subtle depth signal.
- **Upper right:** Shakti, with **Ask Glow** as the action that unfolds the one persistent intelligence.

The world name, Glow OS identity, Return Anchor zone and Shakti do not jump to different positions per page.

A page title belongs below or within the room architecture. It may not rebuild the global top band.

## 4. Shakti and Ask Glow naming law

**Shakti = the intelligent presence.**  
**Ask Glow = the action/conversation state.**

There is one Shakti placement in the permanent shell. Activating Shakti opens the existing centralized Ask Glow conversation.

Page-local Ask Glow controls may remain only as contextual aliases to the same root intelligence. They may not create another assistant or another permanent floating trigger.

## 5. One Glow Current Rail

The left-edge movement system is one app-level Glow Current Rail.

It is not a permanent conventional sidebar.

- The current room remains the clearest local signal.
- Nearby meaningful destinations appear as subtle nodes.
- Labels reveal on touch, hover, keyboard focus, or explicit expansion.
- The rail remains in the same conceptual position and keeps the same movement meaning across rooms.
- Each world may provide different nearby destinations, but it may not create a new rail runtime.

Desktop may express the Current as a vertical edge field. iPad may use a thinner touch-expanding edge current. iPhone may use a compact edge-held current. Meaning remains identical.

## 6. One contextual Return Anchor

The Return Anchor is one physical object with one location, material behavior and motion language.

Its **destination is contextual** so page depth is understandable:

- deep object/subpage → parent room
- room → current major world
- major world root → Today
- Today root state → no unnecessary return action, while the geometry remains stable

Examples:

- Focus Session → Today
- Event Detail → Today
- Wardrobe → Closet
- Closet → Life
- skincare product → Skincare

This contextual parent behavior refines the earlier Return Anchor rule without creating separate Back buttons.

## 7. Universal depth signal

The top-center orientation layer includes a subtle connected depth signal.

It is not a conventional website breadcrumb trail.

Previous levels remain softer. The active depth is fully legible. Accessibility modes may expose the complete text hierarchy.

The depth signal must quietly answer how deep the user is without dominating the room.

## 8. One bottom action host

Glow OS has one universal three-zone bottom action layer.

- **Left:** verified local room/view action or Reverse the Current.
- **Center:** the primary verified action for the current mode; when no room action is registered, World Fold remains the stable system action.
- **Right:** verified system state, save/undo/completion state, or another real contextual action.

Rooms may register actions into this host. They may not create a competing fixed global bottom navigation bar.

No decorative or fake action may be inserted merely to fill a slot.

## 9. No navigation inside page templates

A room may have local transforms, objects and depth, but it should not reproduce ordinary pill tabs such as `Overview / Products / Progress / History / Settings` as its primary movement system.

Those concepts should become room-specific transformations where practical: drawers, mirrors, timelines, material layers, stages, archives, object depth, or other meaningful physical information surfaces.

Local controls may exist when they are the clearest accessible control. They are not a second app navigation system.

## 10. One dominant orientation contract

At any moment, the user should be able to understand:

1. Where am I?
2. How do I go deeper?
3. How do I return?
4. How do I ask Shakti / Ask Glow?

Secondary controls must not compete with those four answers.

## 11. Today synchronization

Today rooms inherit the same root shell.

- Morning Brief: Open World. No unnecessary Return Anchor. Day/current actions remain local transforms.
- What Now: Structured Room. Decision architecture is central; global shell does not change.
- Focus Session: Protected Chamber. Surrounding information recedes; Return Anchor and Shakti remain available but quiet.
- Event Detail: Structured Room inside Today, not a separate calendar app shell.
- Next Up: Open transition corridor.
- Later: continuation farther along the same temporal current.
- Tonight: same navigation geometry; only climate changes.
- Tomorrow Preview: remains attached to Today; future exists beyond the present horizon.
- Replan My Day: Protected/Edit Chamber; editing controls use the shared action host when verified.
- Day View: neutral temporal overview; NOW, NEXT, LATER, TONIGHT and TOMORROW are regions of one timeline rather than five primary tabs.

No Today-only navigation authority may replace the root Glow Current shell.

## 12. All other worlds inherit the same shell

Plan, Life, Brain and Create use the same Glow OS identity, Return Anchor physics, depth language, Shakti placement, World Fold, Glow Thread, continuity and responsive meaning.

Their **local navigation identity** changes. The operating-system shell does not.

## 13. Responsive law

Navigation logic is universal. Geometry adapts.

### Desktop

A vertical edge Current may reveal labels through cursor proximity, hover, focus and trackpad behavior.

### iPad

The same Current becomes thinner and touch/hover responsive. Larger spatial previews are allowed.

### iPhone

The Current becomes a compact edge-held field suitable for one-handed reach. Do not introduce a five-icon bottom tab bar.

Across devices, Return Anchor, World Fold, depth, Reverse the Current and Shakti retain the same conceptual meaning.

## 14. AppShell engineering law

`AppShell` is a room-content and atmosphere host only.

It must not own a permanent Sidebar, GlobalHeader, TodayNavigationAuthority-like runtime, world tab row, or duplicate Shakti trigger.

The root `GlowCurrent` owns the universal shell.

## 15. Legacy navigation migration

Legacy page-local rails, old global headers, old fixed docks and conventional navigation may remain temporarily only when required to preserve a working feature during migration.

They are compatibility surfaces, not design authority. New work must not copy them.

Where the root shell provides the same global function, the duplicate legacy global control should be removed or suppressed without deleting the room's actual local functionality.

## 16. Accessibility

Futurism may never make orientation inaccessible.

Provide visible focus, keyboard access, reduced motion, sufficiently large targets, screen-reader labels, persistent names when requested, dyslexia-friendly text support and explicit text navigation fallback where needed.

Accessibility may make Glow Current more explicit. It must not create a separate per-page navigation model.

## 17. Completion test for every room

A room is not complete unless:

- the stable outer Glow OS boundary is present
- the universal top geometry is inherited
- Shakti is in the canonical position and opens the same Ask Glow runtime
- Glow Current Rail remains available
- Return Anchor behavior is contextual and consistent
- the depth signal is truthful
- World Fold remains reachable
- Glow Thread/recent-path memory survives travel
- the bottom action host remains the universal fixed action layer
- page-local global navigation does not compete with the root shell
- enclosure is intentionally Open, Structured or Protected
- iPhone, iPad and desktop preserve the same navigation meaning
- reduced-motion and keyboard behavior remain usable

## Final invariant

**Every Glow OS page inherits the same invisible navigation skeleton. Rooms may change their architecture, materials, atmosphere, scale, dominant object and interaction. They may not redesign the operating system around themselves.**

**Glow OS is one continuous house with many rooms. Glow Current is the permanent movement system that follows the user through all of them.**
