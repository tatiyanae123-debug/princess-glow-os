# Glow OS — Glow Current Global Navigation Lock

**Status:** AUTHORITATIVE / PERMANENT  
**Date:** 2026-09-05  
**Scope:** Every current and future Glow OS world, room, page, subpage, responsive composition, object view, prototype, generated concept, and implementation.

## Core law

Glow Current is one universal navigation system mounted above the entire Glow OS application. It is not rebuilt page by page.

Every current and future page inherits the same navigation physics, state, history, Return Anchor, World Fold, Glow Thread, Shakti continuity, accessibility behavior, and cross-device meaning.

A room may define its own **Navigation Identity** and express the shared physics through its own climate and objects. A room may not replace, hide, contradict, fork, or create a second primary navigation system.

## Supersession rule

This lock supersedes any older Glow OS instruction that defines a permanent sidebar, bottom navigation bar, fixed rail, five-world button row, breadcrumb trail, dashboard navigation grid, page carousel, or other conventional primary navigation.

Older room-local rails may remain temporarily while a room is being migrated, but they are legacy compatibility surfaces only. They must not be treated as the governing navigation model for new work.

Accessibility fallbacks may expose clearer text navigation, arrows, lists, keyboard commands, or conventional controls where necessary. Those are accessibility layers, not Glow OS's primary product language.

## One global layer

The navigation runtime must be mounted once at the application root so it remains alive while routes and rooms change.

The global layer owns:

- Glow Current activation
- World Fold
- Glow Thread / recent path memory
- Return Anchor
- Reverse the Current
- shared movement events
- world-level travel
- cross-room continuity
- keyboard and assistive fallbacks
- reduced-motion equivalents
- device-independent movement meaning

Rooms register context into the global layer. Rooms do not create new navigation runtimes.

## Continuous movement law

The user does not conceptually leave one page and open another.

Movement should preserve:

1. **Positional continuity** — the user understands where they moved.
2. **Contextual continuity** — selected objects and active work remain understandable and, where appropriate, remain alive.
3. **Conversational continuity** — Shakti retains the same conversation and contextual understanding.

Shared route movement should use the Glow Matter continuity field rather than hard cuts where technically possible.

## Canonical movement grammar

The shared navigation grammar is:

- **Focus** — move closer.
- **Reveal** — expose information already present within or behind something.
- **Drift** — move toward a nearby connected region.
- **Transform** — let the current environment become another environment.
- **Orbit** — inspect related material while keeping the current subject central.
- **Dive** — move deeper into the same subject.
- **Surface** — move toward broader context.
- **Reverse the Current** — move backward through the remembered path.

These meanings do not change from page to page.

## World Fold

World Fold is the universal long-distance navigation view.

Today, Plan, Life, Brain, and Create are five major geographic climates, not five floating app buttons.

The World Fold must preserve the current room as the user's center of orientation and expose the larger Glow geography around it.

## Glow Thread

Glow Thread is the shared remembered journey across rooms. It replaces conventional breadcrumbs as the primary path-memory concept.

The thread must persist through route changes for the current session and support Reverse the Current / recent-space return behavior.

## Return Anchor

Return Anchor is the stable route back toward the immediate present / Today.

It is global and follows the user into every room. It is not a conventional Home tab.

## Shakti

Shakti remains the one persistent intelligence inside every room and participates in Glow Current rather than becoming a separate navigation system.

Natural-language navigation such as `take me to skincare`, `show me my week`, `go back`, or `where was that birthday thing?` should resolve into movement through the same shared Glow Current architecture.

No page may create a weaker page-specific navigation assistant.

## Navigation Identity

Every room must define a local Navigation Identity while inheriting the shared system:

- geography
- arrival
- departure
- neighboring spaces
- deep spaces
- Orbit material
- forward meaning
- backward meaning
- Dive behavior
- Surface behavior
- Shakti role
- local Current expression
- arrival phenomenon
- departure phenomenon
- continuity behavior

A page is incomplete if its local navigation identity contradicts the global Glow Current layer.

## Responsive law

Glow Current keeps the same meaning on every device.

### iPhone

Prioritize one-handed access, touch, hold, pull, object interaction, Shakti, and a reachable World Fold. Do not add a five-icon bottom navigation bar.

### iPad

Use larger spatial previews, multitouch, hover where available, and larger World Fold geography.

### Desktop

Use cursor proximity, hover, trackpad gestures, scroll depth, drag, keyboard acceleration, and spatial previews. Do not regress into a permanent sidebar application.

## Accessibility

Provide reduced motion, visible focus, keyboard access, screen-reader names, sufficiently large targets, persistent labels where requested, dyslexia-friendly text options, and explicit text navigation fallbacks when needed.

Accessibility may make the system more explicit. It must not require a separate page-specific navigation model.

## Engineering rule for future pages

Do not ask: `What navigation bar should this page have?`

Ask:

- Where does this room exist?
- What is beside it?
- What is deeper inside it?
- What does forward mean here?
- What does backward mean here?
- What does Dive reveal?
- What can Orbit without leaving?
- How does Shakti guide movement here?
- What survives when the user travels elsewhere?

## Acceptance criteria

A page is not complete unless:

- Glow Current remains available without page-specific setup.
- World Fold can be reached.
- Return Anchor remains available.
- recent path memory survives room changes.
- shared navigation state is not reset by the page.
- the page does not introduce a competing primary sidebar, tab bar, or five-world button row.
- keyboard and reduced-motion behavior remain functional.
- iPhone, iPad, and desktop preserve the same navigation meaning.
- Shakti and active conversation continuity remain available.
- route movement uses the shared continuity mechanism where possible.

## Final invariant

**Glow OS is one navigable living world. Glow Current is mounted once, follows the user everywhere, and every room inherits it. Rooms may have different identities, but they do not have different navigation systems.**
