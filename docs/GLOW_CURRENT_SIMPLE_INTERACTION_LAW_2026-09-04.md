# Glow Current — Simple Interaction Law

This implementation law clarifies the canonical Glow Current navigation constitution. It supersedes any interpretation that makes gesture vocabulary required for ordinary Glow OS use.

## Governing rule

**Visible interaction must be simple. Underlying navigation physics may be sophisticated.**

The user should normally see a clear object, control, destination, or piece of information and press it. Glow OS then performs the continuous movement, context preservation, material transformation, and orientation behavior underneath that simple action.

A user must never need to memorize terms such as World Fold, Reverse the Current, Dive, Surface, Orbit, or Navigation Field in order to use Glow OS.

## Primary visible interaction

The default interaction is:

**See destination → Press destination → Glow transforms toward it → Context remains attached.**

Examples:

- Press **Glow OS** → return to the new Glow OS Home.
- Press **Today** → open Today through the current Glow Matter transition.
- Press **Focus** → Focus becomes the active room while Today context remains connected.
- Press **Ask Glow** → open Glow's conversational intelligence.
- Press an appointment → that appointment expands into its working environment.

## Advanced Glow Current vocabulary

World Fold, Glow Thread, Orbit, Dive, Surface, Reverse the Current, Temporary Currents, and related concepts remain valid Glow Current physics and future advanced capabilities. They are not required operating instructions.

They may appear as:

- optional shortcuts,
- power-user gestures,
- accessibility alternatives,
- contextual enhancements,
- internal transition logic,
- future discoverable interactions.

They must never replace reliable visible controls before those controls work.

## Visual preservation law

Navigation implementation must not overwrite an approved room design.

When a room has a locked reference image or approved live state:

- preserve its architecture,
- preserve its Glow Matter treatment,
- preserve its object placement,
- preserve its approved visible controls,
- improve only the movement between destinations unless the user explicitly requests a visual redesign.

**Reference image = visual source of truth.**

**Glow Current = behavioral movement system underneath the reference.**

## Product-facing naming

The conversational control is **Ask Glow**.

Do not show **Ask Shakti** as the primary product-facing command label unless the user explicitly changes this rule later. Shakti may remain part of Glow OS's internal intelligence/presence architecture, but the command the user presses is Ask Glow.

## Reliability law

Every visible navigation control must do something understandable on press.

Do not ship visible controls that only look interactive.

Do not require hidden gestures to make visible controls work.

Do not route users into old legacy layouts simply because a new region is not finished. Keep them inside the current Glow Matter generation with a connected preview or unfinished-room state until the new room is ready.

## Home law

Glow OS Home remains the true central orientation environment.

The Glow OS wordmark always returns there.

Home is not the old dashboard and must never route to the old dashboard generation.

## Accessibility and discoverability

Advanced navigation can be taught gradually, but ordinary use must remain obvious without instruction. Reduced Motion, keyboard, touch, pointer, and accessibility paths should preserve the same meaning.

## Final implementation principle

**Simple controls. Futuristic movement.**

The user should feel that Glow OS is spatial and continuous without having to think about how the navigation system is engineered.
