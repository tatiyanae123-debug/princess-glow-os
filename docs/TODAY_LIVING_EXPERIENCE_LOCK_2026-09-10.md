# Glow OS — Today Living Experience Family Lock

Date: 2026-09-10
Status: Governing implementation law

## Core rule

Today is one living day, not a collection of independent pages. Morning Brief, What Now, Focus Session, Event Detail, Next Up, Later, Tonight, Tomorrow Preview, Replan My Day and Day View are projections of the same Day Object and the same underlying Glow Objects.

Canonical flow:

Life → Sources → Glow Objects → Glow Graph → Current State → Intent → Intelligence → Decision → Action → Result → Learning → Updated Life Model.

## Non-negotiable implementation requirements

1. A task, event, routine, person, file, location or preparation item keeps one canonical identity wherever it appears.
2. No Today room may create a duplicate page-local source of truth for an object already represented in the Life Model.
3. Room changes may change composition, art direction, controls and intelligence, but not object identity.
4. Current time, available time, readiness, energy, urgency, dependencies, progress and future pressure are first-class state.
5. What Now is a Context + Intent + Decision projection. Recommendations must be ranked and explain themselves in compact decision receipts.
6. Focus is a protected execution chamber connected to the active task, its subtasks, resources, blockers and session history.
7. Event Detail is a full event-object dossier connecting participants, preparation, agenda, files, location, joining actions and travel context when those sources exist.
8. Next Up is a transition/readiness surface, not merely a next-calendar-event card.
9. Later and Tonight have distinct temporal compositions and emotional modes. They must not be generic template swaps.
10. Tomorrow Preview identifies light preparation and context that reduce tomorrow friction.
11. Replan is a simulation chamber. Proposed changes remain staged until explicit user approval. External calendars are never silently mutated.
12. Day View is the compressed master temporal lens. NOW, NEXT, LATER, TONIGHT and TOMORROW are regions of one timeline, not primary tab siblings.
13. Actions produce receipts containing prior state, next state, affected objects, external-write status and undoability.
14. Undo is architectural. It must reverse eligible local staged actions and never pretend an external change was reverted unless it actually was.
15. Ambient intelligence belongs throughout the interface as small context-aware explanations rather than repeated long AI prose.

## Visual lock

Today uses a spatial, luminous, editorial life-operating environment. The reference language includes warm pearl/champagne/ivory foundations, foggy blush and pale lavender, soft blue iridescence, refractive glass, volumetric light, specular highlights, internal reflections, caustic blooms, low-contrast shadows and depth-aware transparency.

Iridescent Glow matter is semantic visual material. Large liquid forms, pearls, droplets, rings, flow lines and waves communicate importance, state and temporal/emotional mode. They are not random decoration.

Typography is editorial and mode-aware. Large headings may use dramatic scale and thin weight; metadata stays quiet; selected quotes may use a serif/editorial voice. Shared tokens are allowed, but every Today room retains its own composition.

The contextual right rail changes purpose per experience:
- Morning: synthesis and recommendations
- What Now: decision explanation
- Focus: protection, resources and blockers
- Event: join, details, files and travel
- Next Up: time and readiness
- Day View: rhythm, priorities, notes and ambient support

## Reference-family rule

The ten locked reference screens are one experience family. Recreating them as ten isolated screenshots is incorrect even if they look visually accurate. The correct implementation is page-specific art direction on top of one shared living model.
